# Public Experience Contract

This document records the user-facing language and navigation rules that keep the repository coherent across the README, command line, reports, figures, tests, contribution paths, and releases.

## Canonical Terms

Use:

- **reported records**
- **synthetic demonstration**
- **date-order warning**
- **general analysis**
- **reporting-delay calculation**
- **open this first**
- **what the results mean**
- **what this does not establish**

Avoid retired or unclear expressions such as:

- calendar-order flag,
- negative calendar order as primary user-facing language,
- verified sighting,
- confirmed event,
- proof,
- causation without supporting evidence.

## First-Timer Journey

The public experience follows:

1. Understand the subject.
2. Understand the evidence boundary.
3. Learn the project story.
4. See a synthetic example.
5. Explore without installation.
6. Run the safe demonstration.
7. Open one clearly identified result.
8. Read interpretation before detailed statistics.
9. Understand record accounting.
10. Use authorized data through template, validation, and analysis.
11. Contribute or report security concerns safely.
12. Verify the exact release artifact.

## Product Invariants

- Synthetic examples are visibly labeled.
- No real witness narratives or personal data are included.
- Source CSV files are never modified.
- Existing output is protected unless `--force` is explicit.
- Material warnings require explicit acknowledgment.
- Analysis-specific exclusions remain visible.
- Unsupported statistics are marked `Not calculated`.
- Reports do not verify events or establish causation.
- The release is tied to one exact reviewed commit and checksum.

## Required Human Starting Point

Every run identifies:

```text
analysis-summary.md
```

as the first result to open.

## Maintenance Rule

A wording or navigation change is incomplete until the README, CLI, generated reports, figures, tests, contribution guidance, and release notes remain aligned.
